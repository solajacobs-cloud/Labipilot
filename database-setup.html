Backend setup

Connect LabiPilot to its own Supabase project.

This guide keeps LabiPilot separate from other apps and prepares the waitlist for real saved signups.

Safe setup sequence

Use a dedicated Supabase project for LabiPilot. Do not reuse Richflo, Labiright, or any other existing production database.

  1. Create a new Supabase project named LabiPilot.
  2. Open the SQL editor in that new project.
  3. Run the schema from supabase-schema.sql.
  4. Copy the project URL and anon public key from Supabase project settings.
  5. Add the values to Vercel environment variables only after the site code is ready to submit live records.
  6. Submit a test waitlist record and confirm it appears in the labipilot_waitlist table.

Current schema

The first production table is intentionally small. It saves name, email, interest, source, and created date. Row Level Security is enabled.

public.labipilot_waitlist
id uuid primary key
name text required
email text required
interest text optional
source text default website
created_at timestamptz default now()
