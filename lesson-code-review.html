Lesson 03

Read the generated code before changing it.

AI can create a working first draft, but builders still need to know which files control layout, behaviour, forms, data, and deployment.

Goal

This lesson trains learners to inspect a generated app calmly before asking for changes. The point is not to become a senior developer overnight. The point is to know where to look and how to request focused fixes.

Code reading checklist

  1. Find the main page file and confirm the visible sections match the product brief.
  2. Find the stylesheet and check spacing, colour, mobile layout, and reusable classes.
  3. Find the script file and identify form handling, copy buttons, menus, and progress tracking.
  4. Check links against real files or routes.
  5. Ask for one focused fix at a time, then verify it in the browser.

Review prompt

Use this after AI generates or edits code. It forces the review to focus on visible product behaviour.

Review this generated app before I make more changes.
Check:
1. which file controls the main page
2. which file controls styling
3. which file controls form behaviour
4. broken links or missing pages
5. mobile layout risks
6. unclear or duplicated code
7. the safest next fix
Return findings in priority order with exact file names.
